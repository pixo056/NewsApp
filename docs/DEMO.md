# Живая демонстрация «Пульса»

Сценарий примерно на 5 минут для кейса «Умное решение для ленты новостей». До выступления проверьте его на том же компьютере и в той же сети, которые будете использовать на защите.

## Подготовка

1. Запустите `start.cmd` либо `start-wifi.cmd` для показа с телефона в одной Wi-Fi-сети. Дождитесь сообщения с адресом. Ноутбук должен оставаться включённым.
2. Откройте обычное окно браузера для автора и отдельный профиль/приватное окно для ADMIN. Пароли находятся только в своей `.local/accounts.txt`; не показывайте этот файл на проекторе.
3. У автора должна быть подтверждена почта. В локальном прототипе письма доступны через тестовый ящик на компьютере-сервере.
4. Подготовьте новость: заголовок, не менее 50 символов текста, небольшую фотографию либо короткий MP4/MOV. Укажите реальную ссылку, если материал взят из другого источника.
5. Уберите из демонстрационной ленты случайные тестовые материалы через CMS. Убедитесь, что в выбранном паблике остался суточный лимит для новой заявки и одной правки.

## Порядок показа

| Время     | Действие                                                                                       | Что объяснить                                                                                                                      |
| --------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:40 | Открыть ленту гостем, категорию и полную новость                                               | Студент читает без регистрации, видит автора/паблик, источник, фото или видео. Видео запускается по нажатию                        |
| 0:40–1:10 | Показать настройки оформления и узкий экран                                                    | Три темы сохраняются на устройстве; интерфейс адаптируется к экрану                                                                |
| 1:10–1:50 | Войти автором, подписаться на паблик, открыть «Подписки», поставить эмодзи и сохранить новость | Подписки относятся к пабликам. Одна реакция на новость заменяется новым выбором; сохранённое доступно после повторного входа       |
| 1:50–2:50 | Открыть паблик, нажать «Предложить новость», заполнить и отправить форму                       | Получатель закреплён за пабликом. До одобрения заявка видна автору со статусом, а гостю новость недоступна                         |
| 2:50–3:35 | В отдельном окне ADMIN открыть CMS, выбрать заявку, проверить вложение и одобрить              | Для всех пабликов действует обязательная проверка администрацией. У владельца нет кнопки одобрения своих новостей                  |
| 3:35–4:20 | Обновить ленту, изменить свой опубликованный заголовок, снова открыть новость гостем           | Новая версия ждёт решения, прежняя остаётся публичной. ADMIN может одобрить правку либо отклонить с причиной                       |
| 4:20–5:00 | Показать причину/уведомление, раздел жалоб и документацию                                      | В CMS есть управление пабликами, пользователями и жалобами; права проверяет сервер. Показать результаты проверок из CASE_REVIEW.md |

На защите называйте проверенным то, что действительно запускали. Web-интерфейс и адаптивность не подтверждают готовые APK/IPA. Тестовый почтовый ящик не отправляет настоящие письма. Локальный запуск не означает публичный сервер.

## Ресурсы и готовые решения

CMS использует свободную React-admin и существующие API/базу приложения. Отдельный CMS-сервер и отдельная база для неё не нужны. Публичная лента загружает модуль CMS только при переходе в управление.

Локальный запуск ограничивает Java heap диапазоном от 64 до 512 МиБ. Это ограничение памяти Java-объектов, а не общего потребления компьютера: остаются память JVM вне heap, PostgreSQL, Node, браузер и обработка видео FFmpeg. На другой машине повторите измерение и нагрузочную проверку. Java 25, PostgreSQL и Node остаются обязательными компонентами текущего стека.
