# Передача NewsApp: запуск, использование и проверка

Проект «Пульс» — локальная новостная платформа для университетского сообщества. Это работающий React-интерфейс с Java backend, PostgreSQL и загрузкой медиа. Для работы нужен запущенный компьютер-сервер. GitHub хранит исходники, а не работающий сервис и не пользовательскую базу.

## 1. Что получает следующий разработчик

Стек: React 19 + TypeScript + обычный CSS, Vite для разработки и сборки; Java 25, Spring Boot 3.5.16, Spring Security/JDBC/Validation, Flyway; PostgreSQL 17.6. Фото/видео хранятся локально, видео обрабатывают FFmpeg и ffprobe. Kafka, JPA, Docker и внешние сервисы для текущего запуска не нужны.

В репозитории есть интерфейс, backend, SQL-миграции, тесты, Windows-лаунчеры, исходники Capacitor для Android/iOS, локальные шрифты и публичные демонстрационные изображения. Есть демонстрационные паблики и новости, которые сервер создаёт при первом запуске новой базы.

В репозитории **нет** базы прежнего разработчика, загруженных им фото/видео, аккаунтов его тестовых пользователей, действующих паролей, локального IP и резервных копий. При первом запуске на новом компьютере создаются собственные данные и случайные пароли. Демонстрационный контент создаётся из исходников; пользовательские материалы предыдущего компьютера не появятся.

## 2. Установка на Windows с нуля

Нужны Windows x64, интернет для первой установки зависимостей, JDK **25**, Node.js **24** (допустим 22.12+) и pnpm **11.25.0**. Также используется стандартный `tar.exe` Windows. JDK должен включать инструменты разработки. Если Java автоматически не найдена, задайте `JAVA_HOME` на её каталог и заново откройте терминал.

Скачайте исходники через GitHub → Code → Download ZIP и распакуйте либо выполните:

```powershell
git clone https://github.com/pixo056/NewsApp.git
cd NewsApp
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
.\start.cmd
```

Откроется `http://localhost:5173/`. Первый запуск дольше обычного: скачиваются переносимые Maven, PostgreSQL и FFmpeg, собирается Java backend, создаётся кластер базы и стартовые материалы. Инструменты устанавливаются внутри `.local/`; системная PostgreSQL не требуется. Первоначальная установка зависит от доступности источников скачивания.

Оставьте окно запуска открытым. `Ctrl+C` останавливает frontend/backend, которые запустило это окно. Для полной остановки, включая PostgreSQL, выполните `stop.cmd`. Данные при остановке сохраняются. Для последующих запусков достаточно `start.cmd`.

| Команда               | Назначение                                                          |
| --------------------- | ------------------------------------------------------------------- |
| `start.cmd`           | Полный запуск для этого компьютера; автоматически открывает браузер |
| `start.cmd --no-open` | Тот же запуск без открытия браузера                                 |
| `start-wifi.cmd`      | Полный запуск с доступом телефона из той же Wi-Fi-сети              |
| `stop.cmd`            | Остановка процессов данного проекта и его PostgreSQL                |
| `pnpm dev`            | Только frontend; backend/база должны уже работать                   |
| `pnpm build`          | Проверка TypeScript и сборка frontend в `dist/`                     |

Не запускайте другой режим поверх работающего: сначала `stop.cmd`, затем нужный лаунчер. После Java-изменений также остановите приложение и запустите снова: Windows блокирует работающий JAR. Изменения React/CSS подхватывает Vite.

## 3. Логины, пароли и восстановление

На первом запуске создаётся файл **`.local/accounts.txt`**. Откройте его у себя в Проводнике/редакторе. Он содержит пароли двух заранее подтверждённых локальных аккаунтов:

| Логин         | Назначение                                                                               |
| ------------- | ---------------------------------------------------------------------------------------- |
| `uunit.admin` | Администрация платформы; управляет официальным пабликом «УУНиТ» и модерирует все новости |
| `club.owner`  | Владелец обычных пабликов «IT-сообщество» и «Спорт в кампусе»; модерирует их новости     |

Пароли случайные и отличаются на разных компьютерах. Не ищите пароль в GitHub и не используйте пароль другого участника команды. Обычные пользователи регистрируются через интерфейс; администратора через публичную регистрацию получить нельзя.

**Где находятся данные авторизации:**

- `.local/accounts.txt` — первоначальные пароли двух демонстрационных аккаунтов, для удобства владельца компьютера.
- `.local/config.json` — локальный пароль PostgreSQL и первоначальные пароли демонстрационных аккаунтов для запуска/создания новой базы.
- PostgreSQL, таблица `app_users` — актуальные аккаунты и BCrypt-хеши паролей. Открытых пользовательских паролей в таблице нет.
- Сессии — в памяти backend; браузер хранит HttpOnly cookie. После перезапуска Java может потребоваться войти снова.

Файлы accounts/config не синхронизируются с изменениями паролей через интерфейс. Если пароль аккаунта сброшен, актуален новый пароль из базы. Редактирование config или повторный запуск не меняет пароль уже существующего пользователя. Не удаляйте config при сохранённой базе: можно потерять настройки подключения к ней.

### Тестовая почта

Настоящая отправка email **не подключена**. После регистрации войдите и откройте «Тестовая почта» на компьютере-сервере: `http://localhost:5173/dev/mailbox`. Выберите письмо своего пользователя и перейдите по ссылке подтверждения. Так же работает восстановление пароля через «Забыли пароль?».

Этот общий ящик показывает тестовые письма всех локальных аккаунтов, включая ссылки сброса паролей. Поэтому его чтение через Wi-Fi запрещено. Для пользователя телефона владелец компьютера открывает письмо через localhost и подтверждает адрес; затем пользователь телефона обновляет страницу. Подтверждение в таком режиме **не доказывает владение настоящим email**. Письма и данные токенов хранятся в PostgreSQL.

## 4. Кто и что модерирует

| Где предложена новость                                                  | Кто принимает решение                                                |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| От личного аккаунта, без паблика                                        | Администратор платформы `uunit.admin`                                |
| В официальном паблике «УУНиТ» или другом паблике с официальным статусом | Администратор платформы                                              |
| В обычном пользовательском паблике                                      | Его создатель-владелец; администратор платформы тоже может вмешаться |

Любой подтверждённый пользователь может предложить материал в любой паблик. Это отправка на рассмотрение, а не немедленная публикация от имени сообщества.

Обычный пользователь создаёт собственный паблик через «Паблики» → создание паблика. Его создатель получает права модерации этого паблика. Дополнительных редакторов и передачи владения через интерфейс пока нет. Владелец может одобрить собственное предложение, но всё равно должен пройти действие модерации.

Официальный статус назначает только администрация платформы. Если обычный паблик становится официальным, его владелец больше не принимает решения по публикациям как модератор обычного паблика: это делает администрация. Значок официального статуса — настройка демонстрации; подключённой проверки реальной принадлежности УУНиТ нет.

### Публикация и правки

1. Автор открывает «Предложить новость», выбирает личную публикацию или паблик, категорию, вводит текст и при необходимости прикрепляет медиа/источник.
2. После отправки в «Моих публикациях» появляется статус «На модерации». Гостю новая заявка и её медиа недоступны.
3. Модератор входит своим аккаунтом и открывает **«Управление сайтом»**, адрес `/cms` (старый `/admin` перенаправляет туда). Он видит только доступные ему заявки.
4. Одобрение публикует новость. При отклонении обязательно указать причину; автор видит статус, причину и уведомление.
5. Редактирование опубликованной новости создаёт новую заявку. До одобрения правок читатели видят предыдущую одобренную версию. Отклонение правок не скрывает её.
6. Повторная правка заменяет предыдущую ожидающую заявку; устаревшее решение нельзя применить второй раз. Одобрение правок не переносит новость в начало ленты.

Удаление собственной новости убирает её из публичного чтения. Данные ревизий и журнал решений сохраняются. Это не физическая очистка базы/файлов.

### Жалобы и управление

- Подтверждённый пользователь открывает новость → «Пожаловаться», указывает причину и описание.
- В кабинете модератора есть вкладка **«Жалобы»**: можно записать решение и скрыть публикацию. Доступ соответствует правилам модерации выше.
- Вкладка **«Паблики»** показывает доступные сообщества. Из неё можно перейти на страницу паблика; `uunit.admin` меняет там суточный лимит и официальный статус. Владелец обычного паблика редактирует доступные ему сведения о своём сообществе.
- Вкладка **«История»** доступна ADMIN и показывает последние 100 записей журнала административных решений. Это не полный журнал всех действий каждого посетителя.
- Раздел «Пользователи» доступен ADMIN: поиск, изменение имени/описания, блокировка с причиной и восстановление доступа. Блокировка завершает сессии. Выдача роли ADMIN и удаление аккаунтов через интерфейс не предусмотрены. Полная инструкция — [CMS.md](CMS.md).

Подписки, сохранения, новости, группы и реакции сохраняются в PostgreSQL после перезапуска. Тема хранится в localStorage конкретного браузера. Работа на другом устройстве требует отдельного входа в аккаунт.

### Действующие ограничения

- Заголовок: **10–150** символов; текст: **50–10 000**, с пробелами. С видео текст может отсутствовать. Сервер считает Unicode code points.
- Фото: **до 4**, каждое до **10 МиБ**, JPG/PNG/WebP; сервер проверяет изображение, преобразует в JPEG и уменьшает длинную сторону до 1920 px. Ограничение исходного изображения — 24 мегапикселя.
- Видео: **одно**, MP4/MOV, до **200 МиБ / 3 минут / 1080p**. FFmpeg создаёт MP4 H.264/AAC и обложку. Обработка может занять время; одновременно обрабатывается одно видео.
- Фото и видео в одной новости не смешиваются; GIF отдельно не поддерживается. Видео запускается нажатием, не автоматически.
- Источник: укажите HTTP/HTTPS-ссылку при использовании чужого материала. Для оригинальной новости поле может быть пустым; автоматического поиска плагиата нет.
- Обычно **5 предложений/правок на аккаунт в сутки**, по времени Asia/Yekaterinburg; отклонённые заявки тоже считаются. Есть отдельный лимит паблика. Для владельца при отправке в собственный паблик действует его повышенный лимит; у ADMIN нет личного потолка, но сохраняется потолок паблика.

Видеолимиты приведены к требованиям: до 3 минут и 200 МиБ. Сервер проверяет реальную длительность и разрешение, форма заранее проверяет размер файла. Обработка ограничена 9 минутами и одним видео одновременно.

## 6. Проверка с телефона по Wi-Fi

На новом компьютере **не нужно вписывать адрес прежнего владельца в код**. Wi-Fi-IP определяется при запуске автоматически. В тестах используются условные адреса для документации, они не являются адресом чьего-либо ноутбука.

1. Подключите компьютер и телефон к одной обычной Wi-Fi-сети.
2. Если приложение запущено, выполните `stop.cmd`.
3. Запустите `start-wifi.cmd`. При первом запуске подтвердите системный запрос Windows для правила брандмауэра.
4. Скопируйте показанный адрес из строки `PHONE (same Wi-Fi): http://<IPv4 вашего компьютера>:5173/`. Он также находится в **`.local/wifi-url.txt`**.
5. Откройте адрес в браузере телефона. На компьютере используйте `http://localhost:5173/`, особенно для тестовой почты.
6. Не закрывайте окно запуска и не отправляйте компьютер в сон. После смены IP/Wi-Fi остановите и запустите режим заново, используйте новый адрес.

Frontend доступен только выбранному Wi-Fi-интерфейсу/его подсети и loopback; backend `127.0.0.1:8080` и PostgreSQL `127.0.0.1:55432` не открываются в сеть. Rule `NewsApp-WiFi-5173` ограничен конкретным node.exe, TCP 5173 и текущими адресами/интерфейсом Wi-Fi. Профиль сети и настройки роутера не меняются.

Если телефон не открывает страницу: проверьте адрес/порт, что сервер продолжает работать, одинаковую сеть, VPN и изоляцию устройств в гостевой сети. При отказе UAC входящий доступ может остаться закрытым. Для возврата к доступу только на компьютере: `stop.cmd` → `start.cmd`. Удалить созданное правило можно в PowerShell администратора:

```powershell
Remove-NetFirewallRule -Name NewsApp-WiFi-5173
```

**Текст для передачи проверяющему:** «Запусти проект у себя через start-wifi.cmd, подключи телефон к той же Wi-Fi-сети и открой адрес, который напечатает скрипт. Никакие мои IP и пароли переносить не нужно. Твои локальные пароли будут в .local/accounts.txt. Для подтверждения зарегистрированных пользователей открывай тестовую почту на компьютере через localhost».

## 7. PWA, Android и iOS: фактическая готовность

Манифест, иконки, режим standalone и service worker существуют. Service worker сохраняет только экран отсутствия связи и иконки. Новости, API, почта и сессии офлайн не кэшируются.

В Wi-Fi-режиме сейчас **HTTP**, локальный HTTPS ещё не настроен. На телефоне можно добавить ярлык сайта, но полноценная установка PWA и автоматическое предложение установки не подтверждены. Для этого нужен HTTPS, которому доверяет телефон, и проверка установки в целевом браузере. Простого пропуска предупреждения о недоверенном сертификате недостаточно. Установка PWA не переносит backend на телефон.

`android/` и `ios/` — сгенерированные исходники Capacitor, **не готовые APK/IPA**. Нативные сборки/подписи и проверка на устройствах не выполнены. Для Android нужны SDK/Android Studio; для iOS — macOS/Xcode. В текущей конфигурации оболочка смотрит на localhost; Android-разработка использует `adb reverse`. Не заменяйте этот адрес чужим Wi-Fi-IP без понимания режима. Подробности в [MOBILE.md](MOBILE.md).

| `android/`, `ios/`                                     | Исходники оболочек без локальных настроек/сборок                                | Да                   |
| `pnpm-lock.yaml`, pom/Gradle-файлы                     | Зафиксированные зависимости/параметры сборки                                    | Да                   |

Не кладите пароли в `VITE_*`: эти значения доступны клиентскому JavaScript. `.gitignore` уже исключает перечисленные локальные файлы. Исключение не защищает файл, ранее принудительно добавленный через `git add -f`; проверяйте состав коммита перед отправкой.

После `git add` выполните `pnpm check:publication`: проверка читает именно индекс Git, ищет локальные файлы/приватные адреса, известные форматы токенов и совпадения с текущими секретами `.local/config.json`, не печатая значения. Она не заменяет ручной просмотр и не проверяет историю уже существующего удалённого репозитория.

Для передачи кода достаточно клона/ZIP исходников. **Не архивируйте всю рабочую папку с `.local`**. Если понадобится перенос пользовательских данных, это отдельная приватная передача согласованной резервной копии, а не публичный GitHub.

### Резервная копия

```powershell
.\stop.cmd
.\scripts\backup-local.ps1
```

Архив появится в `.local/backups/`, включает секреты. Физическая копия требует остановленной PostgreSQL. Восстанавливать её следует в отдельный пустой локальный каталог с совместимой PostgreSQL 17 и закрытыми процессами; не распаковывать поверх работающей базы. Для обычного ознакомления с проектом копия не нужна.

## 9. Приёмочная проверка

Для независимых сессий используйте разные браузеры/профили, приватное окно или компьютер + телефон. Две обычные вкладки одного браузера обычно используют один аккаунт.

1. На новой локальной базе проверьте гостевую ленту и открытие новости.
2. Найдите пароли в accounts.txt. Войдите `uunit.admin`, откройте `/admin`: в начальных данных есть демонстрационная заявка в официальный паблик, если её ещё не рассмотрели.
3. Зарегистрируйте отдельного автора, подтвердите адрес через тестовую почту. Предложите личную новость: до одобрения её не должен видеть гость.
4. Под ADMIN отклоните заявку с причиной. Проверьте статус и уведомление автора. Исправьте и повторно отправьте, затем одобрите.
5. Предложите новость в «УУНиТ»: `club.owner` не должен иметь права её одобрить, ADMIN должен.
6. Предложите новость в «IT-сообщество»: `club.owner` должен увидеть и одобрить её. Посторонний пользователь не должен видеть очередь.
7. Создайте новый обычный паблик под автором, отправьте туда материал другим пользователем. Создатель должен получить доступ к его модерации. Проверьте перевод паблика в официальный под ADMIN.
8. Отредактируйте опубликованную новость: гостю до одобрения видна старая версия. После отклонения правки она остаётся; после одобрения появляется новая.
9. Проверьте фото, видео/обложку/воспроизведение и отказ при неверных размерах/форматах. До одобрения вложения не должны выдаваться постороннему.
10. Проверьте поиск, категории, подписку/отписку, сохранение/удаление из сохранённого, реакцию и сохранность после повторного входа.
11. Подайте жалобу от автора, рассмотрите её модератором, укажите решение и скройте новость. Проверьте публичную ленту и историю решений ADMIN.
12. Проверьте сброс пароля через локальное письмо и завершение старой сессии. После смены пароля accounts.txt не обновляется автоматически.
13. Через Wi-Fi проверьте вход, публикацию/загрузку файлов, узкий экран и длинный текст без пробелов. `/dev/mailbox` и `.local` с телефона должны оставаться недоступными.
14. Остановите и снова запустите приложение. Материалы/паблики/подписки должны сохраниться; вход может понадобиться повторно.

### Автоматические проверки

После успешного первого запуска, из корня проекта:

```powershell
pnpm build
pnpm format:check
pnpm test:frontend
pnpm test:cms
pnpm test:launcher
node --experimental-strip-types --test config/network-access.test.ts
.\scripts\test-backend.ps1
# При работающем start.cmd или start-wifi.cmd:
node scripts/smoke-local.mjs
node scripts/smoke-cms.mjs
```

Backend-тесты используют отдельную базу `newsapp_test`, а HTTP smoke — рабочую локальную базу. Smoke создаёт тестового пользователя/новость, проходит сценарий и скрывает тестовую публикацию; это не полностью бесследная проверка. Не направляйте его на чужую или производственную базу. Если демонстрационным аккаунтам меняли пароль через интерфейс, smoke с первоначальными паролями config не войдёт.

В ветке улучшений пройдены сборка frontend, 24 backend-теста с PostgreSQL, 8 frontend-тестов, 4 сетевые проверки и 10 проверок запуска. Полный HTTP smoke прошёл через работающий Vite proxy, включая повторные просмотры. В браузере проверены вход, 150 emoji в заголовке, ошибки текста/источника, отправка на модерацию, мгновенное обновление ленты при подписке и отсутствие горизонтального переполнения на узком экране. Проверен обычный запуск через start.cmd. Проверки не подтверждают подключение физического телефона по Wi-Fi, нативные APK/IPA и установку PWA на Samsung.

## 10. Если что-то не запускается

| Симптом                           | Что проверить                                                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Java 25 not found                 | Установлен ли JDK 25; корректен ли JAVA_HOME; перезапущен ли терминал                                          |
| Node/pnpm not found               | Установить Node и pnpm, открыть новый терминал, выполнить установку зависимостей                               |
| Порт занят / другой режим         | Остановить проект через stop.cmd; проверить другой Vite/Spring/PostgreSQL, не завершать чужие процессы вслепую |
| Не скачиваются инструменты        | Интернет/доступность Maven Central и источника FFmpeg, логи установки                                          |
| Не собирается JAR                 | Остановить работающий backend перед сборкой                                                                    |
| Не удаётся войти                  | Пароль именно из своей .local; после сброса нужен новый; config не обновляет существующего пользователя        |
| Нельзя публиковать/создать паблик | Подтверждена ли почта, не исчерпана ли квота, валидны ли поля/файлы                                            |
| Новость не видна в ленте          | Одобрена ли она, не скрыта ли по жалобе, не включён ли фильтр категории/подписок                               |
| На телефоне нет тестовой почты    | Это намеренное ограничение; открыть её на компьютере через localhost                                           |
| Нет кнопки установки PWA          | Wi-Fi-режим HTTP; требуется доверенный HTTPS и проверка браузера                                               |

Логи: `.local/logs/backend.log`, `backend-error.log`, `frontend.log`, `frontend-error.log`, `postgres.log`. Путь важен, но содержимое логов не следует автоматически публиковать: там могут оказаться локальные сведения.
