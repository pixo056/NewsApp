# Только локальная работа

По указанию пользователя внешнего размещения нет. Не создавались облачные серверы, домены, S3-бакеты, SMTP-аккаунты и публикации в магазинах приложений. Прежняя конфигурация контейнера только для демонстрационного frontend удалена, чтобы её не принимали за запуск полного приложения.

Рабочий способ запуска — `start.cmd`. Он использует Java 25, встроенную в IntelliJ либо найденную по JAVA_HOME, переносимые Maven/PostgreSQL и локальные FFmpeg/ffprobe. Данные `.local` не входят в Git и недоступны через Vite. База `newsapp` постоянная, `newsapp_test` отдельная для тестов.

По умолчанию порты только loopback: frontend 5173, backend 8080, PostgreSQL 55432. `start.cmd --no-open` запускает без автоматического открытия браузера. `stop.cmd` останавливает зарегистрированные им процессы, проверяя PID, время запуска и путь программы, и останавливает кластер PostgreSQL данного проекта. Чужие процессы по имени не завершаются.

`start-wifi.cmd` включает доступ с телефона в той же Wi-Fi-сети. Frontend слушает IPv4-интерфейсы; middleware разрешает loopback и адреса подсети выбранного физического Wi-Fi-интерфейса, пришедшие на его IP, включая проверки WebSocket. VPN-интерфейсы не выбираются. Правило брандмауэра `NewsApp-WiFi-5173` разрешает только TCP 5173 для конкретного node.exe, локального Wi-Fi-адреса/интерфейса и его подсети. Оно действует и для Public-профиля, поскольку Windows может считать домашнюю сеть публичной; профиль сети не меняется. Создание/обновление правила требует обычного системного подтверждения администратора Windows. Внешних публикаций и проброса портов роутера нет.

Оба запуска поддерживают `--no-open`. При переключении режима сначала `stop.cmd`. Текущий адрес телефона печатается в терминале и `.local/wifi-url.txt`. После изменения IP/сети нужен перезапуск Wi-Fi-режима. Для возврата к loopback — `stop.cmd`, затем `start.cmd`; удалить правило можно командой `Remove-NetFirewallRule -Name NewsApp-WiFi-5173` в PowerShell администратора.

При повторном запуске работающие серверы используются повторно. После изменения Java-кода сначала остановить приложение, затем запустить заново: Windows блокирует открытый JAR от перезаписи. При ошибке смотреть `.local/logs/backend.log`, `backend-error.log`, `frontend.log`, `frontend-error.log`, `postgres.log`.

Резервная копия: остановить приложение и PostgreSQL, выполнить `scripts/backup-local.ps1`. Скрипт откажется снимать физическую копию работающей базы. Он создаёт ZIP в `.local/backups`, не удаляет рабочие данные и не отправляет архив наружу. Восстанавливать только в новую локальную папку, с PostgreSQL той же основной версии и остановленными процессами.

Локальный почтовый ящик открыт только через localhost на ноутбуке и предназначен исключительно для тестирования. В Wi-Fi-режиме Vite перезаписывает внутренний маркер доступа для proxy, а backend запрещает удалённым посетителям читать ящик. Новые пользователи с телефона просят владельца ноутбука подтвердить адрес через локальный ящик. Перед возможным будущим размещением потребуются отдельное согласование, реальные HTTPS/SMTP/медиа-хранилище, новые секреты и отключение тестового ящика. Сейчас это не выполнялось.
