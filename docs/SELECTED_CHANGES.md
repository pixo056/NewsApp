## Публикация и две независимые проверки

| Материал           | Первая проверка                                | Где появляется после неё                                | Проверка общей ленты    |
| ------------------ | ---------------------------------------------- | ------------------------------------------------------- | ----------------------- |
| Обычный паблик     | Создатель паблика; ADMIN также может вмешаться | Страница паблика, подписки, сохранённые и прямая ссылка | Отдельное решение ADMIN |
| Официальный паблик | ADMIN                                          | Паблик и общая лента                                    | Та же проверка ADMIN    |
| Личная новость     | ADMIN                                          | Общая лента                                             | Та же проверка ADMIN    |

Войдите владельцем → «Управление сайтом» → «Публикации» → «На проверке» → откройте заявку → «Одобрить в паблике». После этого ADMIN увидит её в списке «На проверке» и в отдельном фильтре «Проверка для общей ленты». Откройте материал и нажмите «Одобрить для общей ленты» либо отклоните с причиной. Владелец эту вторую проверку выполнить не может. Собственная заявка создателя также требует его явного решения.

При отказе в общей ленте публикация сохраняется в паблике и подписках. Автор видит отдельную причину в «Моих публикациях» и уведомление. Для повторной проверки автор отправляет исправленную версию. Скрытие новости по жалобе убирает её из всех публичных мест; восстановить скрытую может только ADMIN.

Редактирование создаёт новую заявку. Пока создатель её не одобрил, в паблике остаётся прежний текст. После его одобрения в паблике появляется новая версия, а общая лента продолжает показывать прежнюю версию до отдельного решения ADMIN. Карточки передают идентификатор версии в ссылке: переход из общей ленты не подменяет проверенный текст новой версией паблика. Произвольная старая или черновая версия по такой ссылке гостю недоступна. Фото/видео доступны публично только если входят в одну из двух текущих одобренных версий.

Общий поиск ищет версии общей ленты; поиск с ограничением паблика/подписок — версии соответствующего раздела. Сохранённое показывает последнюю одобренную версию паблика. Дата первой публикации сохраняется отдельно для паблика и общей ленты; одобрение правок не поднимает старую новость наверх.

В PostgreSQL `news.published_revision_id` — версия паблика/обычной публикации, `news.main_revision_id` — версия общей ленты. `news_revisions.status` хранит первое решение, `main_status` — решение общей ленты: `waiting` (ещё нет первой проверки), `pending`, `published`, `rejected`, `withdrawn` (версия заменена). Причины, проверяющие и даты сохранены отдельно. `main_published_at` — дата первого размещения в общей ленте. Миграция V5 сохраняет уже опубликованные новости и переносит их в обе ленты; повторно модерировать старый контент не требуется. Пароли, аккаунты и загрузки не сбрасываются.

## Простые рекомендации

Блок «Найдите своих» получает до трёх пабликов с нескрытыми публикациями за последние 30 дней. Выше — больше свежих публикаций. При одинаковой активности порядок меняется раз в день по времени Екатеринбурга и остаётся стабильным в течение дня. Уже подписанные паблики исключаются на сервере. Для гостя подписки отсутствуют. Если подходящих пабликов нет, показывается пустое состояние; старые/пустые паблики искусственно не продвигаются. Интересы, просмотры и персональные профили не собираются.

## Поиск

Для новостей и пабликов: явное приведение русского и латинского регистра, `ё` → `е`, удаление крайних и повторных пробелов, включая неразрывные и переносы строк. Правила одинаково применяются к запросу и полям. `%` и `_` — обычные символы, не шаблон SQL.

Новости: точное совпадение нормализованного заголовка → начало заголовка → вхождение в заголовок → вхождение в текст. Внутри одной группы — новые первыми. Курсор учитывает ранг, дату и id, чтобы постепенная загрузка не пропускала результаты. Паблики: точное название выше вхождений в название/описание. Серверная функция `news_search()` работает в существующей PostgreSQL с локалью C; менять локаль или пересоздавать базу не нужно. Для большого каталога позже можно добавить поисковый индекс после измерения нагрузки.

## Темы

Доступны «Светлая», «Тёмная», «Как на устройстве». Последний вариант выбран на новом устройстве по умолчанию, использует `prefers-color-scheme` и реагирует на изменение системной темы без перезагрузки. Старый выбор `lavender` трактуется как системный. Настройка хранится в браузере в `localStorage` под `newsapp-theme`, отдельно на каждом устройстве.

Тёмное оформление распространяется на сайт и CMS: панели, таблицы, шапку, формы, окна подтверждения, баннеры, статусы, ошибки и превью медиа. Миниатюра светлой темы в настройках намеренно остаётся светлой; цвета аватарок, иллюстраций и самих фото сохраняются.

## Быстрая проверка

1. Запустите `start.cmd` либо `start-wifi.cmd`, дождитесь готовности. Локальные начальные пароли — `.local/accounts.txt`.
2. Предложите новость обычному паблику. Создателем одобрите в CMS: в паблике видна, в «Все новости» отсутствует.
3. Администратором откройте очередь общей ленты. Сначала проверьте отказ и сохранность паблика; на другой заявке — одобрение и появление в общей ленте.
4. Отредактируйте одобренный материал. Пройдите обе проверки и сравните версии при переходе из паблика и из общей ленты.
5. Ищите `Ёжик в кампусе`, `ЕЖИК   В КАМПУСЕ` и тот же запрос с переносами/неразрывными пробелами. Сравните новости и названия пабликов; точный заголовок должен быть выше частичных совпадений.
6. Откройте настройки: все три темы, перезагрузка страницы, смена системной темы в режиме «Как на устройстве». Проверьте и `/cms` под модератором.

Автоматические проверки: `pnpm test:frontend`, `pnpm test:cms`, `pnpm test:network`, `pnpm test:launcher`, `scripts/test-backend.ps1`; HTTP-сценарии — `scripts/smoke-local.mjs` и `scripts/smoke-cms.mjs` при запущенном приложении. Тесты backend используют отдельную базу `newsapp_test`. Проверки не означают проверку физического Android/iOS или установки PWA.

Проверено 22.10.2026: **64 backend + 12 frontend + 5 CMS provider + 4 сетевых + 10 лаунчера = 95 проверок**, два HTTP-сценария и production-сборка. Дополнительно проверены V1→V5 и начальные материалы в отдельной временной схеме тестовой базы, публичность медиа двух одобренных версий и закрытость чернового вложения. В тесте очистки просмотров выявлена зависимость размера удаления от плана PostgreSQL: выборка 500 ключей закреплена `MATERIALIZED`, ограничение подтверждено прежним регрессионным тестом.

Через браузер проверены два решения CMS на временной новости, тёмная панель/таблицы/диалоги, выбор «Как на устройстве» и совпадение с текущим системным режимом; настройки при ширине 390 px без горизонтального переполнения. Временные новости скрыты. Переключение самой темы Windows и физический Samsung в этом прогоне не проверялись.
