# Реализованная архитектура

React/TypeScript + Vite → `/api` proxy → Spring Boot 3.5.16 на Java 25 → PostgreSQL 17.6. Медиа находятся в `.local/media`, FFmpeg/ffprobe запускаются локально. По умолчанию все серверы слушают только loopback. В режиме `start-wifi.cmd` frontend доступен выбранной Wi-Fi-подсети; backend и PostgreSQL остаются на loopback. Docker, внешние сервисы, S3, SMTP и размещение самого приложения не используются.

## Доступы

Гость читает только одобренные новости и их медиа. USER предлагает новости, создаёт обычные паблики, подписывается, сохраняет, реагирует и жалуется. Подтверждение почты нужно перед публикацией/созданием паблика/жалобой.

ADMIN создаётся Seeder заранее (`uunit.admin`, пароль генерирует локальный setup). Он проверяет личные публикации, официальные паблики и может вмешаться в любые обычные. Владелец обычного паблика модерирует его заявки/правки и жалобы независимо от автора. После назначения официального статуса эти права владельца прекращаются. Самоназначения ADMIN через регистрацию нет.

Любой подтверждённый пользователь может открыть паблик и предложить материал с его страницы. Получатель закреплён в форме. До одобрения администрацией материал не попадает в ленту. Назначение дополнительных редакторов не реализовано: у паблика один создатель-владелец. Создание самого паблика пока не требует отдельного одобрения.

Поле `canModerate` аккаунта означает доступ к CMS: оно истинно для ADMIN и владельца обычного паблика. Это не разрешение одобрять новости. В объекте новости `canModerate` истинно только для ADMIN; сервер проверяет роль при каждом решении независимо от интерфейса.

## Ревизии и транзакции

News хранит author_id/community_id и два указателя: latest_revision_id и published_revision_id. Создание и изменения порождают pending-ревизии. Публичные запросы используют только published_revision_id. До решения по правкам старая версия остаётся доступна. Отклонённая правка не скрывает опубликованное. Одобрение правок сохраняет первоначальный published_at и порядок ленты.

Предыдущая неподтверждённая заявка при новой правке становится withdrawn. Одобрить устаревшую или уже рассмотренную заявку нельзя. Блокировки строк защищают решения модераторов и проверку квот от гонок. Суточная граница — Asia/Yekaterinburg. Правки и отклонённые заявки расходуют квоту.

По умолчанию 5 заявок на аккаунт в сутки. У паблика собственный потолок. Если пользователь — создатель выбранного паблика, его персональный потолок для этой отправки равен лимиту паблика. Общая история личных/пабличных заявок пользователя учитывается при проверке. ADMIN освобождён от личного потолка, но потолок паблика сохраняется.

Удаление новости мягкое (`deleted`): она исчезает из ленты/сохранённого и её медиа больше не выдаются гостю. Ревизии/аудит остаются. Загрузивший пользователь сохраняет доступ к собственным файлам. Отдельный DELETE медиа разрешён только владельцу и только для ещё не привязанного файла.

## Аккаунты

Spring Security, серверные сессии, HttpOnly/SameSite=Lax cookie, CSRF-токен в заголовке всех изменений. Login использует стандартную форму Spring; JSON API получает CSRF через `/api/auth/csrf`. Пароль — BCrypt. Восстановление использует случайный одноразовый токен; в таблице account_tokens хранится его SHA-256, токен истекает через 30 минут. Подтверждение почты — 24 часа. Сброс пароля завершает старые сессии.

Тестовая почта доступна только при `app.local-mailbox=true`, через localhost на компьютере-сервере и показывает письма всех локальных пользователей. Через Wi-Fi чтение запрещено: Vite перезаписывает доверенный маркер для proxy, backend проверяет его и loopback-адрес. Она имитирует почтовый транспорт и не доказывает владение реальным email. В базе писем присутствуют ссылки с токенами. Это режим разработки; публикация исходников не делает приложение публичным сервисом.

## API

Все пути ниже имеют префикс `/api`.

| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Аккаунт            | GET /auth/me, /auth/csrf; POST /auth/register, /auth/login, /auth/logout, /auth/forgot-password, /auth/reset-password, /auth/verify-email, /auth/resend-verification; PATCH /me |
| Новости            | GET /news?category=&q=&communityId=&subscriptions=&saved=&cursor=&limit=; GET /news/{id}; POST /news; POST /news/{id}/revisions; DELETE /news/{id}; POST /news/{id}/view        |
| Автор              | GET /me/news, /me/news/{id}, /me/preferences                                                                                                                                    |
| Паблики            | GET/POST /communities; PATCH /communities/{id}; PUT/DELETE /communities/{id}/subscription                                                                                       |
| Сохранения/реакции | PUT/DELETE /news/{id}/bookmark; GET /news/{id}/reactions; PUT/DELETE /news/{id}/reaction                                                                                        |
| Медиа              | POST /media (multipart file); GET /media/{id}, /media/{id}/poster; DELETE /media/{id}                                                                                           |
| Модерация          | GET /admin/revisions; POST /admin/revisions/{id}/approve или /reject; POST /admin/news/{id}/hide                                                                                |

Лента возвращает `{ items, nextCursor }`; курсор — пара published_at/id. Сортировка DESC по обоим. Поиск через параметризованный ILIKE по заголовку/тексту, фильтр категории — точное совпадение. Размер страницы ограничен 50. Каталог пабликов фильтруется по названию на клиенте.

## Просмотры и ограничения запросов

`POST /news/{id}/view` возвращает `{ views, counted }`. Одна одобренная новость получает не более одного просмотра за 24 часа от аккаунта, даже в разных браузерах. Для гостя используется текущая серверная сессия: удаление cookies или новая сессия позволяют новый просмотр. Это защита от повторного обновления страницы, а не доказательство уникального человека.

Миграция V2 добавляет `news_viewers`; существующие счётчики сохраняются. В таблице хранятся SHA-256 ключи аккаунтов/сессий и время последнего засчитанного просмотра. IP и исходные идентификаторы сессий не записываются. Повторный просмотр не продлевает окно. Блокировка строки новости и уникальный ключ исключают двойной подсчёт параллельных запросов. Истёкшие записи удаляются порциями до 500 не чаще раза в минуту при чтении; исторический счётчик не уменьшается. Для скрытых, ожидающих и отсутствующих новостей возвращается 404.

Vite заменяет `X-NewsApp-Client-IP` адресом своего socket-соединения. Backend использует его для лимитов входа, регистрации, восстановления и просмотров только при подключении с loopback. Пользовательские `Forwarded`/`X-Forwarded-For` не используются. Это разделяет лимиты Wi-Fi-клиентов и не открывает тестовую почту: её проверка по-прежнему использует отдельный маркер и реальный loopback-адрес. При замене Vite другим proxy нужно воспроизвести эту границу доверия; backend остаётся на loopback.

## Обработка медиа

Локальная multipart-загрузка, прогресс на клиенте. Фотографии проверяет ImageIO, ограничение 24 мегапикселя, затем преобразование в JPEG и уменьшение длинной стороны до 1920. Видеофайлы проверяет ffprobe; проверяются реальный контейнер, видеодорожка, длительность и размеры. Затем FFmpeg приводит их к H.264/AAC MP4, создаёт JPEG poster. Одновременно обрабатывается одно видео, время обработки ограничено. Аргументы передаются ProcessBuilder без shell, сетевые протоколы входного ffprobe/FFmpeg ограничены.

Файлы не выдаются статически: контроллер проверяет загрузившего файл, автора связанной новости, текущую одобренную открытую ревизию, роль ADMIN либо владельца её обычного нескрытого паблика. Владелец может проверить вложение чужой заявки перед решением; скрытие или официальный статус прекращают этот доступ без авторства. HTTP Range работает для проигрывания видео. До одобрения файла нет в публичной ленте. Серверные ограничения: фото до 10 МиБ, видео до 200 МиБ/3 минут/1080p; 4 фото либо одно видео на ревизию.

## Проверки

Интеграционные тесты проверяют права/скрытые заявки, ревизии, регистрацию без повышения роли, CSRF, одноразовые токены, фотографии, приватность, видео/HTTP Range, подписки/поиск/курсоры, гонку 7 одновременных отправок при квоте 5 и доступ к почте только на компьютере-сервере. `config/network-access.test.ts` отдельно проверяет границы Wi-Fi-доступа на условных адресах RFC 5737.

Отдельный HTTP smoke проверяет cookies и CSRF через реальный Vite proxy, регистрацию/подтверждение, смену сессий, медиа, предмодерацию администрацией, ревизии, реакции, сохранения после повторного входа, жалобу/скрытие и сброс пароля с инвалидированием прежней сессии. Актуальные результаты текущей проверки фиксируются в [CASE_REVIEW.md](CASE_REVIEW.md).

Совместимость Java 25: https://docs.spring.io/spring-boot/3.5/system-requirements.html . PostgreSQL binaries: Maven Central `io.zonky.test.postgres:embedded-postgres-binaries-windows-amd64:17.6.0`. FFmpeg: https://ffmpeg.org/download.html → Windows builds by gyan.dev.

## CMS

Панель React-admin загружается отдельно по `/cms/*`, использует существующие сессии/CSRF и серверный `/api/cms`. Списки `{items,total}` фильтруются по правам до подсчёта и пагинации; сортировка выбирается по allowlist. Владелец видит свои обычные паблики, все их нескрытые заявки и жалобы, принимает решения и может скрыть материал. Пользователи, общий аудит и восстановление скрытого доступны только ADMIN. Чужой текст владелец не переписывает, собственные материалы редактирует через новые ревизии. Они сохраняют автора, паблик и опубликованную версию. Проверки доступа учитывают официальный статус под блокировкой community → news. Неопубликованные медиа доступны автору, ADMIN и владельцу соответствующего обычного паблика; после скрытия владелец без авторства теряет доступ. Гостю доступны только медиа одобренной открытой новости.

Миграция V3 добавляет blocked/block_reason. `/api/cms/users` доступен только ADMIN и возвращает явный список полей без секретов; PATCH допускает только имя, описание и блокировку с причиной. Блокировка завершает сессии, запрещает вход, отзывает токены и проверяется при обращении с устаревшей авторизацией. Роль, почта и пароль этим API не меняются. Полный список ресурсов и действия описаны в [CMS.md](CMS.md).

## Реакции

Миграция V4 добавляет `reactions.kind` с четырьмя допустимыми значениями: `like`, `celebrate`, `insightful`, `support`. Существующие записи получают `like`; ключ `(user_id,news_id)` сохраняет ограничение одной реакции аккаунта на новость. `PUT /news/{id}/reaction` принимает `{"kind":"support"}` и заменяет прежний выбор, `DELETE` снимает его. Для совместимости PUT без тела означает `like`.

`GET /news/{id}/reactions` возвращает `{counts,selected,total}`. `counts` содержит все четыре вида, включая нулевые; `selected` — выбор текущего аккаунта или `null`. Счётчики доступны гостю только для опубликованной нескрытой новости. PUT/DELETE требуют сессию и CSRF; проверка видимости и изменение выполняются под блокировкой строки новости. Лента и полная новость также возвращают `reactionCounts` и `myReaction`; прежние поля `reactions` и `liked` сохранены для совместимости.
