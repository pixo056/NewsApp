# Сверка с кейсом «Умное решение для ленты новостей»

Источник: предоставленная пользователем презентация от 21.10.2026, 5 слайдов. Проверка проекта начата 22.10.2026. Этот документ описывает требования к прототипу, а не подтверждение допуска или оценки экспертного совета.

## Что требует презентация

| Слайды | Пункт                                                         | Состояние на начало проверки                                                                                                                                               |
| ------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2–3    | Лента студенческих мероприятий, понятный адаптивный интерфейс | Есть: публичная лента, категории, поиск, страницы новостей, паблики                                                                                                        |
| 2      | Возможность применения скинов                                 | Есть: светлая, тёмная и лавандовая темы в настройках                                                                                                                       |
| 2–3    | Добавление новостей, фото, видео и графических материалов     | Есть: личные публикации и предложения со страницы паблика, до 4 JPG/PNG/WebP либо одно MP4/MOV; PNG/WebP можно использовать для афиш и инфографики                         |
| 2–3    | Обязательная предмодерация перед основной лентой              | Есть очередь и версии; требуется согласовать единое правило с пожеланием пользователя: все новости и правки одобряет ADMIN, владелец обычного паблика не одобряет сам себя |
| 3      | Реакции, возможно эмодзи                                      | Есть один лайк; расширяем до нескольких понятных реакций с одной выбранной реакцией на аккаунт                                                                             |
| 3      | Подписка на новости                                           | Есть подписки на паблики и отдельная лента подписок                                                                                                                        |
| 2–3    | Готовая CMS допускается, freeware и открытый код              | Есть свободная React-admin (MIT) поверх собственного Java API; внешний платный сервис не используется                                                                      |
| 3      | Нетребовательность к ресурсам и серверному ПО                 | Локальные PostgreSQL, Java и Node, CMS загружается отдельно; ресурсные ограничения и измерения уточняются в ходе проверки                                                  |
| 3, 5   | Работоспособность, тесты, архитектура, документация           | Есть автоматические тесты и HTTP-сценарии; после доработок требуется повторная проверка и сценарий живой демонстрации                                                      |

Виртуальные баллы на слайде 3 приведены как дополнительный пример мотивации. Они не являются обязательным условием кейса. Награды за массовые реакции без защиты от накрутки не добавляем.

Многоплатформенность проверяется в web-интерфейсе. Готовую сборку APK/IPA, реальный SMTP, университетский SSO и публичное размещение эта сверка не подтверждает.

## План доработок

1. Ограничить одобрение и отклонение новостей администрацией, сохранить владельцу работу со своими материалами и настройками паблика.
2. Добавить реакции «Нравится», «Поздравляю», «Интересно», «Поддерживаю» с сохранением прежних лайков.
3. Проверить роль владельца в CMS, повторить проверки приложения и описать демонстрацию для защиты.

Каждый готовый этап сохраняется отдельным коммитом в ветке `feature/presentation-alignment`. Локальные пароли, база и пользовательские файлы не публикуются.
